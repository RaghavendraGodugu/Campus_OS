# CampusOS

**From Student Problems to Digital Solutions.**

A unified college management and student service platform. Every student request
becomes one digital request with one owner, one workflow, one status and one
auditable resolution.

### What is implemented

- Session auth: short-lived access token plus rotating refresh token, both in
  `HttpOnly` `SameSite=None` cookies
- **Refresh token reuse detection**: replaying a spent token revokes every
  session and invalidates outstanding access tokens
- Stateless double-submit CSRF, bound to the user and session via HMAC
- 13-role permission matrix (`domain:action:scope`); absence means denial
- Role changes take effect on the next request — the user is re-read per request
- Confidential-complaint access restricted to `DEAN` and `PRINCIPAL`, and
  deliberately **not** granted to `SUPER_ADMIN`
- Audit log with automatic redaction of free text, so the trail cannot leak
  complaint contents
- `npm run create-admin` and `npm run seed:demo`

### Not yet implemented

Student profiles beyond the `Student` model, the request engine, complaints,
certificates, invoices, payments, notifications, announcements, reports, and
the entire frontend. The backend currently serves only `/health` and
`/api/v1/auth/*`.

## Requirements

- Node.js **>= 20.19.0**
- npm 10+
- A MongoDB database. Development currently supports both:
  - **MongoDB Atlas** (production, recommended) — paste the SRV string into
    `campusOs_backend/.env` as `MONGO_URI`
  - **A local MongoDB** for offline work — e.g. `mongodb://127.0.0.1:27017/campusos_dev`

## Setup

```bash
# 1. install dependencies for both workspaces from the repo root
npm install

# 2. create backend + frontend env files from their templates
cp campusOs_backend/.env.example campusOs_backend/.env
cp campusOs_frontend/.env.example campusOs_frontend/.env

# 3. edit campusOs_backend/.env and set at minimum:
#      MONGO_URI, JWT_SECRET, REFRESH_TOKEN_SECRET, CSRF_SECRET
#    Generate secrets with:
#      node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

# 4. create the first SUPER_ADMIN account
npm run create-admin
```

### Running

```bash
npm run dev:backend    # http://localhost:5000
npm run dev:frontend   # http://localhost:5173
```

The Vite dev server proxies `/api` to the backend, so the two run as one origin
in development.

### Testing and linting

```bash
npm test           # backend integration suite
npm run lint
npm run format
```

Backend tests boot an **ephemeral MongoDB** (`mongodb-memory-server`) on a
fixed port, so a test run can never read or delete your development or Atlas
database. A guard hook aborts the run if the connection is anything other than
that ephemeral instance.

To reuse a locally installed `mongod` instead of downloading one:

```bash
export MONGOMS_SYSTEM_BINARY=/opt/homebrew/opt/mongodb-community/bin/mongod
npm test
```

### Switching to MongoDB Atlas

Development was verified against a local MongoDB 8.0 instance. To use Atlas:

1. Paste the connection string into `campusOs_backend/.env`:

   ```env
   MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/campusos_dev?retryWrites=true&w=majority
   ```

2. In Atlas, add your IP to the cluster's **Access List**, or allow
   `0.0.0.0/0` for a development cluster.
3. Restart the server. Indexes are created automatically on connect.

Atlas has **not** been exercised yet — the connection path is untested until
you supply the string.

### Seed data

```bash
npm run seed:demo   # demo departments, request types and role accounts
```

Demo data is generated by a dedicated script and is **labelled as demo in the
interface**. Never present seeded rows as real operational data.

## Architecture rules

These are enforced in code, not convention:

1. **The backend is the only authority.** The frontend may hide actions a role
   cannot perform, but every authorization decision is re-made server-side.
2. **Least privilege.** A role grants only the capabilities in
   `campusOs_backend/src/utils/permissions.js`. Resource-level checks
   (ownership, department, assignment, confidentiality) live in the service
   layer, not just route middleware.
3. **No money in floats.** All amounts are integer paise (`INR * 100`).
4. **No client-authoritative state.** Amounts, roles, student IDs and workflow
   transitions are always derived server-side.
5. **No transactions in auth paths.** Critical writes use single-document
   atomic operations so the backend also runs against a standalone `mongod`.
